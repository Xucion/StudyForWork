聚合函数

分组查询（GROUP BY）

​	SELECT 字段列表 FROM 表名 [WHERE条件] GROUPBY 分组字段名 [HAVING **分组后过滤条件**];

排序查询（ORDER BY）

​	SELECT 字段列表 FROM 表名 ORDER BY 字段1 排序方式1, 字段2 排序方式2;

​	排序方式：ASC 升序（默认）；DESC（降序）

​	SELECT 字段列表 FROM 表名 LIMIT 起始索引, 查询记录数

​	起始索引从0开始，起始索引 = （查询页码 - 1）* 每页显示记录数；如果查询的是第一页的数据，起始索引可以省略，直接写limit 10。

## 关系型数据库vs非关系型

**ACID vs BASE**

​	关系型数据库支持 ACID 即原子性，一致性，隔离性和持续性。

​	NoSQL 采用更宽松的模型 BASE ， 即基本可用，软状态和最终一致性。

**扩展性对比**

​	NoSQL数据之间无关系，这样就非常容易扩展，也无形之间，在架构的层面上带来了可扩展的能力。比如 redis 自带主从复制模式、哨兵模式、切片集群模式。

​	相反关系型数据库的数据之间存在关联性，水平扩展较难 ，需要解决跨服务器 JOIN，分布式事务等问题。

## 数据库三大范式

**1NF**：数据库表的每一列都是不可分割的原子数据项。

**2NF**：在1NF的基础上，非码属性必须完全依赖于候选码。第二范式需要确保数据库表中的每一列都和主键相关，而不能只与主键的某一部分相关（主要针对联合主键而言）。

**3NF**：在2NF基础上，任何非主属性不依赖于其它非主属性（在2NF基础上消除传递依赖）.。第三范式需要确保数据表中的每一列数据都和主键直接相关，而不能间接相关。

## 事务

**四大特性ACID**

​	原子性(Atomicity):事务是不可分割的最小操作单元，要么全部成功，要么全部失败。

​	一致性(Consistency):事务完成时，必须使所有的数据都保持一致状态。

​	隔离性(Isolation):数据库系统提供的隔离机制，保证事务在不受外部并发操作影响的独立环境下运行。

​	持久性(Durability):事务一旦提交或回滚，它对数据库中的数据的改变就是永久的。

**并发事务问题**

​	脏读：一个事务读到另外一个事务还没有提交的数据。

​	不可重复读：一个事务先后读取同一条记录，但两次读取的数据不同，称之为不可重复读。

​	幻读：同一个事务内，两次**相同的**查询得到的结果集**行数不一样**。第二次查询多出来了一些"幽灵般"的行。

### **事务隔离级别**

​	从上至下↓，隔离级别越来越高，性能越来越低。

**一：Read uncoommitted**：指一个事务还没提交时，它做的变更就能被其他事务看到；**发生脏读、不可重复读、幻读**

**二：Read coommitted**：指一个事务提交之后，它做的变更才能被其他事务看到；	**发生不可重复读、幻读**

**实现方式**：**MVCC + 写锁（行锁）**

- **写操作**：对修改的行加**行级排他锁**，直到事务提交才释放
- **读操作（快照读）**：每次执行 `SELECT` 时，都**重新生成一个 Read View（读视图）**，只读取已提交的事务修改

**MVCC 在这里的行为**：

- 每行数据会有多个历史版本（通过 undo log 实现）
- `SELECT` 时，只看 `Read View` 里可见的版本（即已提交事务的修改）
- 每次查询都重新生成 `Read View`，所以**同一个事务内，两次查询可能看到不同的数据**（不可重复读）

**结果**：解决了脏读，但会出现不可重复读和幻读。

**三：Repetable Read（默认）**：指一个事务执行过程中看到的数据，一直跟这个事务启动时看到的数据是一致的，MySQL InnoDB 引擎的默认隔离级别；										**发生幻读**

**实现方式**：**MVCC + 行锁（间隙锁 Gap Lock 是重点）**

- **写操作**：加行锁 + **间隙锁（Gap Lock）**，防止其他事务插入数据
- **读操作（快照读）**：**事务开始时生成一个 Read View**，整个事务期间都使用这个视图，不再重新生成

**MVCC 在这里的行为**：

- 事务开启时（第一次 `SELECT`），生成一个全局的 `Read View`
- 之后无论查询多少次，都读这个历史快照，保证**每次读到的数据一致**（可重复读）
- 其他事务的修改（提交或不提交），对当前事务都不可见

**间隙锁（Gap Lock）的作用**：

- 不仅锁定查到的行，还锁定行之间的“间隙”
- 比如 `SELECT * FROM users WHERE age BETWEEN 10 AND 20 FOR UPDATE`，会锁住 age 在 10~20 之间的所有行 + 这个范围的所有空隙
- 其他事务无法在这个间隙里插入新数据，从而**防止幻读**

**结果**：解决了脏读和不可重复读，并且在 MySQL 的 RR 级别下，通过间隙锁也解决了幻读（但标准 SQL 的 RR 级别是允许幻读的，这里是 MySQL 的特殊实现）

**四：Serializable**：会对记录加上读写锁，在多个事务对这条记录进行读写操作时，如果发生了读写冲突的时候，后访问的事务必须等前一个事务执行完成，才能继续执行；							**都不发生**

## 存储引擎：

​	存储引擎就是存储数据、建立索引、更新/查询数据等技术的实现方式。存储引擎基于表，而不基于库，所以称为表类型。

### InnoDB

​	InnoDB是MySQL的默认存储引擎，具有ACID事务支持、行级锁、外键约束等特性。它适用于高并发的读写操作，支持较好的数据完整性和并发控制。

​	如果应用对事务的完整性有比较高的要求，在并发条件下要求数据的一致性，数据操作除了插入和查询之外，还包含很多的更新、删除操作，那么nnoDB存储引擎是比较合适的选择。

​	xxx.idb文件：xxx代表表名，innoDB引擎的每张表都会对应这样一个表空间文件，存储该表的表结构、数据和索引。

### MyISAM

​	是Mysql早期默认的存储引擎。特点：不支持事务，不支持外键，支持表锁，不支持行锁，访问速度快。

​	如果应用是以读操作和插入操作为主，只有很少的更新和删除操作，并且对事务的完整性、并发性要求不是很高，那么选择这个存储引擎是非常合适的。

### Memory

​	Memory引擎的表数据是存储在内存中的，由于收到硬件、断电问题的影响，只能做缓存/临时表。特点：内存存放，hash索引（默认）。

## 索引

​	索引(index)是帮助MySQL**高效**获取数据的**数据结构(有序)**。在数据之外，数据库系统还维护着满足特定查找算法的数据结构，这些数据结构以某种方式引用(指向)数据，这样就可以在这些数据结构上实现高级查找算法，这种数据结构就是索引。
