AI-0101 设计服务身份和用户上下文

- 责任角色：后端；
- 推荐：服务 JWT + 60 秒内有效的签名用户上下文；
- 用户上下文包含：sub、aud、conversationId、iat、exp、随机 jti；
- 禁止：明文 X-User-Id、模型参数中的 userId、长期可重放令牌；
- 验收：过期、错误 audience、篡改和重放均被拒绝。

# 这段是什么意思

这段是在解决一个核心安全问题：

> `sky-ai-service` 调用 `sky-server` 查询订单时，怎样证明“调用者确实是 AI 服务，而且它正在代表当前登录用户操作”。

这里存在两种身份，不能混在一起：

```
用户浏览器
  │ 用户 JWT：证明“我是用户 1001”
  ▼
sky-ai-service
  │ 服务 JWT：证明“我是可信的 AI 服务”
  │ 用户上下文：证明“我这次代表用户 1001”
  ▼
sky-server
```

### 1. 服务 JWT 是什么

服务 JWT 用于证明请求来自真正的 `sky-ai-service`，而不是用户直接伪造内部接口请求。

例如：

```
Authorization: Bearer <AI服务JWT>
```

`sky-server` 验证后确认：

- 调用者是 `sky-ai-service`
- 令牌没有过期
- 令牌签名正确
- 该服务有权调用 AI 内部接口

它表示“哪个服务在调用”，不表示“正在替哪个用户查询”。

### 2. 签名用户上下文是什么

AI 服务验证用户登录 JWT 后，为本次内部调用生成一个短期签名令牌，例如：

```
{
  "sub": "1001",
  "aud": "sky-server",
  "conversationId": "conv-9876",
  "iat": 1787100000,
  "exp": 1787100060,
  "jti": "b4578b2e-..."
}
```

各字段含义：

| 字段             | 含义                                 |
| ---------------- | ------------------------------------ |
| `sub`            | 当前操作代表的用户 ID，例如用户 1001 |
| `aud`            | 接收方，只允许 `sky-server` 使用     |
| `conversationId` | 此次操作属于哪个客服会话             |
| `iat`            | 令牌签发时间                         |
| `exp`            | 过期时间，建议签发后 60 秒           |
| `jti`            | 本次令牌的唯一编号，用于防止重复使用 |

`sky-server` 验证这个令牌后，才能把用户 1001 写入 `BaseContext`，然后执行：

```
查询订单时必须满足：
order_id = 101 AND user_id = 1001
```

### 3. 为什么不能直接使用 `X-User-Id`

下面这种设计不安全：

```
X-User-Id: 1001
```

因为普通请求头没有签名，攻击者可以改成：

```
X-User-Id: 1002
```

如果后端直接相信它，就可能查询到用户 1002 的订单。

同样，模型工具也不能设计成：

```
{
  "orderId": 201,
  "userId": 1002
}
```

模型生成的参数属于不可信输入。工具参数中只能包含 `orderId`，`userId` 必须由认证上下文注入。

### 4. 为什么只有 60 秒有效期

用户上下文只服务于一次很短的内部工具调用。有效期过长，一旦令牌泄露，攻击者可以长期重复查询用户数据。

60 秒通常足够完成：

```
AI 服务生成令牌
→ 调用 sky-server
→ 查询订单
→ 返回结果
```

具体时间可以配置，但应保持短期有效。

### 5. `jti` 如何防止重放

即使攻击者截获了一个尚未过期的令牌，也可能在 60 秒内重复发送。

`jti` 是一次性编号。`sky-server` 可以在 Redis 中记录：

```
ai:user-context:jti:b4578b2e = used
TTL = 60秒
```

再次收到同一个 `jti` 时就拒绝请求。

不过只读查询是否必须严格“一次性”可以根据复杂度决定。对于写操作必须防重放；P0 只读工具可以先记录和监控，再评估是否启用强制一次性消费。

### 6. 验收条件是什么意思

需要编写测试确保：

- 过期：`exp` 已经过期，拒绝请求；
- 错误 audience：令牌发给其他服务，不允许在 `sky-server` 使用；
- 篡改：把 `sub` 从 1001 改成 1002 后签名失效；
- 重放：同一 `jti` 被重复使用时拒绝或触发安全告警；
- 模型传入 `userId`：参数校验直接拒绝；
- 用户 1001 查询用户 1002 的订单：返回未找到或无权访问，不泄露订单内容。

简单来说，这项设计的目的就是：

> AI 可以替用户查询数据，但用户身份必须来自可信认证链路，不能由用户请求头或大模型自己决定。
